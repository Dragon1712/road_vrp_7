# Step5-A v2 增强审计摘要

审计源：`Dragon1712/road_vrp_7`，Git main `0cf000ce4d1240b109f9160a3a3f59208825cde7`。

### 来自真实Pilot的发现

112/112行运行完成，7变体×2模式×2任务×2情景×2随机种子。Oracle下：baseline 4365.52s；AT-TimeOnly 4320.36s；AT-RR 4291.80s；TE-Local 4321.80s；TE-WR 4364.44s；Both 4329.64s；Placebo-Both 4302.92s。Static下TE-WR 4322.95s而TE-Local 4393.77s。以上样本非常少，数据仅能用来发现问题而非作统计显著结论。

### 已修复的实验解释风险

- 原AT-RR是否实际改变移除集合：现有v1没有影子对照；v2同一次调用产生AT-RR与去交通项的匹配排序，记录移除集合差异率和五项分数贡献。
- 原TE-WR机制与Stage3 Worst：v2加入全路线删除总收益对照；外部性正/负选择数量，以及只选正外部性的对照。
- 原来的`at_timeonly`与`te_local`虽是消融，但仍包含动态OD信息；新增完全静态信息`at_space`、`te_static_local`，并有错位OD签名`at_misaligned`的负对照。
- 原v1只记录operator使用计数：v2在相同官方ALNS接受准则前后记录Destroy×Repair、候选增益、被接受次数、产生新最好结果、计时；完整事件聚合、最多120个样本事件。处理真实观测支持率的审计独立于搜索，避免把完整OSM静态回退误当真实监测交通。

### 尚未解决的问题/限制

1. 事件归因是联合算子组合，不是单独Destroy的因果贡献。相同5秒内日志额外开销改变搜索迭代数，因此只能优先比较v2内部各臂。
2. `TrafficSignature`本质上仍基于历史动态OD/静态OD比值（Oracle），不是部署时可获取的预测模态。独立支持率审计只根据冻结初始解中ETA对近邻路线估计，不代表搜索中所有动态状态。
3. 只有两个配送任务的Pilot远不足以确认算子显著有效。测试集已被探索，未来最终验证应使用其他独立时间范围。
4. 真实官方`alns==7.0.0`必须在Ubuntu Smoke成功后才能称通过生产集成；当前执行环境仅做协议模拟及合成测试。
